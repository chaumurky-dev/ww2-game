# wartide-web

Leptos 0.8 (CSR) frontend for Wartide, built with [trunk](https://trunkrs.dev).

## Run

```sh
# toolchain: rustup target add wasm32-unknown-unknown; cargo install trunk --locked
cd crates/web
trunk serve          # http://127.0.0.1:8081, proxies /api and /ws to localhost:8080
trunk build --release
cargo check -p wartide-web --target wasm32-unknown-unknown
cargo clippy -p wartide-web --target wasm32-unknown-unknown -- -D warnings
```

Note: with Homebrew's `rust` shadowing rustup, put `~/.rustup/toolchains/stable-*/bin` first on `PATH`
so the wasm target is found. If `rust-lld` aborts with a missing `libLLVM.dylib`, set
`DYLD_FALLBACK_LIBRARY_PATH=$HOME/.rustup/toolchains/stable-x86_64-apple-darwin/lib` for the build.

## Layout

- `src/lib.rs` - `App`, router (`/`, `/verify`, `/forgot`, `/reset`, `/lobby`, `/game/:id`,
  `/profile/:username`, `/groups`, `/groups/:slug`, `/leaderboard`, `/settings`). Protected routes
  (lobby, game, groups, settings) are wrapped in `components/guard.rs::Protected`, which redirects to `/`
  once `GET /api/me` says "unauthenticated". `MapCtx` holds the lazily loaded map.
- `src/api.rs` - the only place that talks to the REST backend (gloo-net, `credentials: include`, errors parsed
  into `wartide_protocol::ApiError`; callers show them with `Toasts::api_error`). Covers every endpoint in
  `crates/server/README.md`. `USE_MOCK_GAME_STATE` is the single escape hatch (see below).
- `src/realtime.rs` - `/ws` client: reconnects with back-off while logged in, resubscribes to games, bumps
  `lobby_tick` / `game_tick` signals (lobby list + game summary refetch), pushes chat into `chat_in`, shows
  "Your turn" / "Match found" toasts with links.
- `src/state.rs` - `AuthState` (user from `/api/me`) and `Toasts`.
- `src/model.rs` - UI helpers over protocol types (`PowerExt`, `UnitKind`, `Phase`, game title/seat helpers).
- `src/map.rs` - loads `/assets/map_geometry.json` (`{"view_box","projection","locations":{id:{kind,path,label,
  anchor,bbox}},"decor"}`, regenerated by `scripts/mapgen`, never edited here) and `/assets/map.json` (names, IPC,
  original owners, starting units).
- `src/mock.rs` - local in-game state used while `USE_MOCK_GAME_STATE` is true.
- `src/components/board.rs` - `Board` (SVG, pan/zoom, zoom-dependent labels, unit stacks), `MapPreview`, and the
  `BoardModel` view-model. `decor` is drawn as inert grey land; sea zones alternate two blues by a hash of the id.
- `src/components/` - nav, toasts, modal, countdown, power badge, unit icon (sprite `<use>`), phase bar, action
  panel (per-phase), battle board, chat drawer/log, form fields.
- `src/pages/` - one module per route.
- `styles/app.css` - all styling; power colours mirror `crates/engine/data/map.json`.
- `build.rs` - copies `../engine/data/map.json` -> `assets/map.json` and `../../assets/icons/{sprite.svg,units,powers}`
  -> `assets/icons/` (write-if-changed; the copies are committed so a fresh `trunk` run works too). Single source of
  truth stays in the engine / `assets/` dirs: do not edit the copies.
- `assets/brand/` - logo, wordmark, board texture (from `assets/processed/`), `assets/favicon.png`.

## Live vs mocked

Live against the server: register / login / logout / verify / forgot / reset / resend verification, profile and
settings, public profiles, leaderboards, groups (create, join by invite code, rotate invite, members, roles,
remove, leave, group ladders), games (list, summary, create with `bot_seats`, join by code, start, resign, abandon,
"End turn" via `{"type":"end_turn"}`), chat (history + WS push + send), matchmaking queue, WebSocket notifications.

Still mocked (`api::USE_MOCK_GAME_STATE = true`): the in-game board contents beyond original owners and the engine's
starting units, treasury, phase stepper and the per-phase action panels / battle board (they only log locally and
advance a phase selector). `GameStateView` is opaque JSON in the protocol; wire `GET /games/{id}/state` into
`BoardModel` (`pages/game.rs`) when the engine lands.
